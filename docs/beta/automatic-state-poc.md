# Beta 自动状态识别 PoC 闸门

状态：DeepSeek 隔离 PoC 已实现，等待受控页面人工验证；未进入自动等待模式。

自动状态识别只能在用户明确指定目标网页 AI 编程入口，并提供可授权测试页面信息后开始。在此之前，扩展不含 content script、站点选择器、页面 DOM 读取逻辑或任何 AI 内容采集行为。

获准后必须单独实现隔离适配器，且仅输出 `generating`、`completed`、`needs_user`、`unknown`。当 DOM 变化、判断冲突或状态不确定时，必须停止自动模式并回退到当前手动等待模式，绝不猜测“已完成”。

测试矩阵至少覆盖开始、停止、继续生成、错误、网络异常和刷新；并报告识别覆盖率、误报风险、维护成本及是否建议进入 Beta。

## DeepSeek 网页端 PoC

- 目标域名：`https://chat.deepseek.com/*`。
- 内容脚本：`entrypoints/deepseek.content.ts`；状态机：`src/deepseek-adapter.ts`。
- 传入后台的字段仅为枚举状态和本地观察时间；不读取或传输提示词、回复、代码、输入值、文本节点、Cookie 或账号信息。
- 观察的 DOM 信号仅为预设停止控件的 `aria-label`/`title` 匹配、页面级 `role="alert"` 和可输入编辑器的存在/可用性；匹配结果立即归约为布尔值，不读取或保存页面正文。
- 只有先观察到 `generating`，其后停止生成控件消失且编辑器可用时，才输出 `completed`；首次加载、未匹配信号和状态冲突均为 `unknown`。
- 当前阶段只在 Popup 显示本地状态；不会自动开始或结束等待、自动打开游戏、自动点击或自动切换标签页。

### 受控人工验证矩阵

| 场景 | 预期状态 | 安全要求 |
| --- | --- | --- |
| 首次打开 DeepSeek 对话页 | `unknown` | 不得把空闲页面误报为完成 |
| 发送可复现的短任务并出现停止生成控件 | `generating` | 不读取任务或回复正文 |
| 已观察到生成后，控件消失且编辑器恢复可用 | `completed` | 仅在此前出现过生成时成立 |
| 页面显示错误或需要用户处理的提示 | `needs_user` | 不读取提示文本 |
| 刷新、网络中断、DOM 选择器失效 | `unknown` | 保持手动等待模式，不发完成通知 |

进入自动等待模式前，负责人必须完成上述实测，记录每项结果、误报次数和 DeepSeek 页面版本/日期；若任一场景不稳定，维持当前手动模式。
