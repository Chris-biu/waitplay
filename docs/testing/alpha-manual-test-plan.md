# Alpha 手动测试计划

## 前置条件

1. 运行 `npm install` 与 `npm run build`。
2. 在 `chrome://extensions` 启用开发者模式，并加载 `.output/chrome-mv3`。
3. 打开任意普通网页作为原任务标签页；无需也不应使用 AI 页面内容。

## 测试步骤

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 开始与后台计时 | 在普通网页打开 Popup，点击“开始等待”，关闭 Popup | 会话继续；达到 60/90/120 秒后重新打开 Popup 显示推荐卡 |
| 阈值设置 | 在空闲状态选择 60 秒，开始新会话 | 新会话按 60 秒运行；已开始会话不被改写 |
| 推荐克制性 | 达到阈值后检查原网页 | 不自动打开游戏、不切换标签页、不读取或遮挡原网页 |
| 启动游戏 | Popup 中点击“立即游玩” | 新标签页打开本地占位游戏页；原标签页保持不变 |
| 返回任务 | 游戏页点击“回到 AI 任务” | 原始任务标签页被聚焦；两次操作内可完成返回 |
| 结束与通知 | 在任意网页点击“结束等待”，点击系统通知或其按钮 | 显示“AI 任务可能已完成”；原始标签页被聚焦 |
| 异常标签页 | 开始等待后关闭原始标签页，再结束并点击通知 | 扩展不崩溃；无法聚焦时不误切换到游戏页 |
| 推荐开关 | 关闭“启用游戏推荐”，开始等待并超过阈值 | 不显示推荐卡 |
| 隐私与清除 | 开启本地分析后完成一次流程，点击“清除本地数据” | 仅允许事件字段保存；清除后设置、会话和事件恢复为空/默认值 |
| 卸载 | 卸载扩展 | Chrome 移除扩展本地数据；需人工在 Chrome 中验证 |

## 已知人工验证项

通知权限状态、通知点击后焦点行为、Service Worker 休眠恢复、关闭原标签页与 Chrome 卸载均必须在目标 Windows Chrome 环境手动执行；自动构建无法覆盖这些浏览器行为。
