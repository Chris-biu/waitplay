Waitplay 是一个面向 Windows Chrome 的 Manifest V3 扩展。它并不试图预测 AI 还要多久完成，也不是游戏聚合站；它关注一个更基础的问题：当长任务在后台运行时，如何让用户短暂离开屏幕、又不会失去对工作流的掌控。

当前版本为 **0.1.1 内部受控 Alpha**。产品以“手动等待”为主线，所有休息体验都由用户主动开启，并默认使用本地占位内容。真实第三方游戏、自动化 AI 状态识别和更广泛的平台支持都需要分别通过严格的体验、隐私与权利准入。

> [!TIP]
> **一条简单承诺：** 休息由你主动开始，回到任务比继续休息更容易；无法确定的 AI 状态，绝不伪装成“已完成”。

## ✨ 为什么是 Waitplay

AI 编程、研究与内容生成经常包含无法确定结束时间的等待：模型在运行，用户却不希望反复盯着页面，也不愿被娱乐内容带离工作。Waitplay 的设计目标是让这段空档变得有边界：

- **先回工作，再谈休息**：任何时刻都可以回到原始任务标签页；通知和返回入口优先于休息体验。
- **用户始终拥有最后决定权**：不自动点击、不自动开游戏、不自动切换标签页，也不覆盖 AI 页面。
- **本地优先、最少数据**：不建立账号，不依赖服务端，不上传用户内容或行为数据。
- **内容先准入、后接入**：可以访问的网页不等于可以进入产品；许可证、素材、地区、广告和退出体验都必须核验。
- **宁可未知，不作错误承诺**：AI 页面状态无法确定时，保持 `unknown`，绝不把它猜成“已完成”。

| 🎯 工作流优先 | 🛡️ 隐私优先 | 🧩 内容优先 |
| --- | --- | --- |
| 回到任务永远只需一步 | 用户内容永不离开浏览器 | 先审核，再进入目录 |

## ⚡ 当前能力

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 手动等待 | 可用 | 从任意网页开始或结束等待；阈值可选 60、90、120 秒。 |
| 后台恢复 | 可用 | 使用 Chrome Alarms，在 Popup 关闭或 Service Worker 休眠后仍可恢复计时。 |
| 通知与召回 | 可用 | 结束等待时发送本地系统通知；点击后尝试聚焦原始任务标签页。 |
| 受控推荐卡 | 可用 | 到达阈值后显示非阻断卡片；短等待优先展示短时本地体验。 |
| 本地游戏页 | 可用 | 独立标签页中的本地占位体验，用户手动打开并可随时返回任务。 |
| 本地体验事件 | 可用 | 可选、可清除，且只记录最小事件名称、时间与匿名会话标识。 |
| DeepSeek 状态观察 PoC | Beta | 仅观察最小 UI 信号并在本地显示状态；不读取会话内容，不触发自动操作。 |
| 第三方真实游戏 | 未接入 | 候选内容默认不可启动，等待人工权利和体验核验。 |

## 🧭 体验流程

```text
🌐 打开任意任务网页
      ↓
⏳ 主动开始等待（记录当前标签页）
      ↓
✨ 达到阈值后显示非阻断推荐
      ↓
🎮 用户选择跳过，或手动打开本地休息页
      ↓
🔔 结束等待 / 收到通知 / 点击“回到 AI 任务”
      ↓
🎯 聚焦原始任务标签页；若标签已关闭则安全提示，不跳转到其他页面
```

## 🔐 隐私与安全边界

Waitplay 不读取、保存或上传：

- 提示词、代码、模型回复、网页正文、表单输入和剪贴板；
- Cookie、账号信息、密码、完整浏览历史或 URL 查询参数；
- 任何发送到第三方分析平台的用户内容。

DeepSeek PoC 只检查预设停止生成控件、页面级提醒和可编辑输入控件是否存在，并把结果立即归约为 `generating`、`completed`、`needs_user` 或 `unknown`。只有已观察到生成、随后控件消失且编辑器恢复可用时，才可能显示 `completed`；任何不确定情况都保持 `unknown`。

## 🧾 内容准入

目前扩展只提供本地占位体验。候选的 2048、Flexbox Froggy 和 Grid Garden 均处于 `pending`，没有启动链接或嵌入逻辑。

任何第三方内容进入产品前，都必须由负责人完成并记录：

1. 精确版本的许可证或书面授权，以及必要署名；
2. 字体、图标、音频、插图等非代码素材的再分发权利；
3. 适龄、地区、隐私、账号、广告、外链与付费内容检查；
4. Windows Chrome 中的首次可交互时间、暂停、关闭标签页和安全退出验证；
5. 负责人、核验日期与“通过”结论。

详见 [内容权利台账](docs/content/game-rights-ledger.md) 和 [准入记录模板](docs/content/approval-record-template.md)。

## 🛠️ 安装与开发

### 🚀 从源码加载

```powershell
npm install
npm run build
```

1. 打开 `chrome://extensions`。
2. 启用右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择 `.output/chrome-mv3`。

开发期间可运行 `npm run dev`，然后加载 `.output/chrome-mv3-dev`。

### ⌨️ 常用命令

```powershell
npm test          # 单元测试
npm run typecheck # TypeScript 检查
npm run build     # 生产构建
npm run zip       # 生成 .output/waitplay-0.1.1-chrome.zip
```

技术栈：WXT、TypeScript、React、Chrome Manifest V3。

## 🗺️ 长期路线图

路线图的优先级是**可靠的回归工作流、用户信任与内容治理**，而不是无限增加入口或延长用户停留时间。

### 🟣 阶段 1：完成受控 Alpha（当前）

- 收集少量真实试用反馈，衡量“是否错过 AI 结果”“是否容易回到任务”“通知是否造成打扰”。
- 持续修复通知、焦点恢复、原标签关闭和浏览器恢复中的高优先级问题。
- 让本地体验库在不增加账号、广告、积分或排行榜的前提下，提供更清晰的时长与退出预期。
- 固化安装、回滚、问题报告与隐私说明，使每次 Alpha 构建都可重复验收。

### 🔵 阶段 2：把 AI 状态观察做成可验证的 Beta

- 在已授权的 DeepSeek 测试会话中持续验证生成、完成、错误、刷新和网络异常；保留可复现的测试矩阵与误报记录。
- 只有误报风险可接受时，才评估“建议开始等待”等辅助能力；即使如此也必须保持人工确认，绝不自动点击或自动打开内容。
- 将状态适配器继续隔离为可替换模块：页面 UI 变化、信号冲突或未知状态会立即降级回手动等待。
- 在不读取任何对话内容的前提下，研究其他网页 AI 工具的官方、最小化、用户可见的集成方式。

### 🟢 阶段 3：建设可审计的本地内容体系

- 保持“先审核、后配置”的受控目录：每个条目都有来源、权利记录、适用时长、退出说明与审核负责人。
- 优先研究可以本地分发、快速开始、无广告干扰、可安全退出的轻量体验；未获授权内容始终不能启动。
- 为内容上线、下线和版本替换建立回滚机制，避免某个外部页面变更影响用户工作流。
- 若未来考虑 Steam、网页试玩或商业合作，只能在独立的授权、平台条款、年龄/地区、数据流与用户体验审查全部通过后进行；不把外部可访问性误当成产品授权。

### 🟠 阶段 4：扩展可靠性、无障碍与跨平台

- 改进键盘操作、焦点顺序、屏幕阅读器文本、色彩对比和低干扰视觉模式。
- 在 Windows Chrome 稳定后，评估 Edge、Chrome 其他桌面系统及其他 Manifest V3 浏览器的兼容性，逐平台发布而非一次性承诺。
- 强化离线与异常降级：通知被拒绝、原标签关闭、浏览器重启、内容加载失败时都应有明确、安全且不打断工作的回退路径。
- 以本地、匿名、可关闭的数据帮助定位产品问题；任何新增度量都先经过数据最小化审查。

### 🟡 阶段 5：探索桌面端与团队场景（研究，不承诺上线）

- 研究 Codex 桌面端等工具的官方允许接口或扩展机制；不读取提示词、代码或模型输出，也不绕过应用安全边界。
- 评估“任务完成后提醒用户返回”的跨设备体验，但始终避免监控工作内容或自动替用户操作。
- 在个人版隐私边界被验证后，再讨论团队管理、策略配置或企业部署；这些功能必须默认最小权限、可审计且由用户/组织明确授权。

### 🔴 阶段 6：探索商务游戏合作与大型 Demo（远期）

- 在不改变“随时回到任务”主线的前提下，研究与游戏厂商合作展示的可能性：广告或赞助内容必须清晰标注、可关闭、默认不遮挡工作页面，也不得以奖励、倒计时或误导性设计强迫用户停留。
- 任何商务游戏广告都需要先完成合作授权、适龄与地区限制、隐私数据流、广告素材、落地页和外部跳转审查；不基于提示词、代码、模型输出或页面内容做广告定向。
- 评估接入 Steam 上大型游戏官方 Demo 的可行性，优先使用开发商/发行商明确授权的官方分发入口；不重新托管、破解、嵌入或绕过 Steam 的安装、账号、地区与平台规则。
- Steam Demo 仅作为用户主动选择的独立外部体验：打开前说明体积、安装要求、预计时长和返回方式；Waitplay 不读取 Steam 账号、库存、好友、游玩记录或其他个人数据。
- 在每个合作条目完成权利、质量、性能和安全退出验收前，不把它加入推荐目录。大型 Demo 不应替代短时本地休息体验，而应只面向用户明确选择的较长等待场景。

### ♻️ 可持续运营原则

Waitplay 不以分散注意力、诱导长时间停留或出售用户内容为目标。若未来探索商业模式，前提是：透明、可选择、不读取 AI 内容、不引入未经审核广告、不把奖励或排行榜设计成强制用户停留的机制，并能在不付费时保留核心的安全返回体验。

## 🚫 明确不做

- 账号体系、社交关系、积分、排行榜、奖励和强制留存机制；
- 自动点击、自动打开游戏、自动切换标签页或注入/遮挡 AI 页面；
- 云游戏、未审核第三方内容抓取、未经授权的嵌入或重新分发；
- 读取或上传用户提示词、代码、模型输出、Cookie 或账号数据；
- 将“未知”AI 状态包装成“任务已完成”的推断。
